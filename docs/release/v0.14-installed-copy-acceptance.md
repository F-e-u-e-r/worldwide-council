## Acceptance criteria (owner, 2026-09-28)

1. The plugin is installed from an actual marketplace source (a git-served marketplace, so the
   install is a **copy** under the plugins cache), not loaded in place from the repository.
2. The session starts from a working directory unrelated to the repository.
3. All 37 `council-*` agents resolve at runtime (`claude --agent religion-council:council-…`).
4. Agents read their skill / reference resources from the installed copy — no dead repo-relative
   path, and no read of the development checkout (falsification arm).
5. The controller MCP server starts from the installed copy and writes its run state under
   `${CLAUDE_PLUGIN_DATA}`, never inside the plugin root or the source tree.
6. Missing resources fail loud (the agent reports "not found"), never a silent fallback to a
   local checkout.

## Procedure (reproducible; all state in a scratch plugins root)

```bash
S=<scratch dir>; export CLAUDE_CODE_PLUGIN_CACHE_DIR="$S/plugins-root"   # isolates every plugin record
# 1. Snapshot the working tree into a scratch git repo and serve it over smart HTTP
#    (Claude Code clones marketplaces with --depth 1; dumb HTTP and file:// are refused).
rsync -a --exclude .git --exclude .religion-council ./ "$S/src/"; git -C "$S/src" init -q; git -C "$S/src" add -A; git -C "$S/src" commit -qm snapshot
git clone -q --bare "$S/src" "$S/marketplace.git"; git -C "$S/marketplace.git" update-server-info
mkdir -p "$S/cgi-root/cgi-bin"; printf '#!/bin/sh\nexport GIT_PROJECT_ROOT=%s GIT_HTTP_EXPORT_ALL=1\nexec git http-backend\n' "$S" > "$S/cgi-root/cgi-bin/git"; chmod +x "$S/cgi-root/cgi-bin/git"
(cd "$S/cgi-root" && python3 -m http.server --cgi 8766 --bind 127.0.0.1 &)
# 2. Install as a real copied plugin, from an unrelated directory
mkdir -p "$S/unrelated-cwd"; cd "$S/unrelated-cwd"
claude plugin marketplace add http://127.0.0.1:8766/cgi-bin/git/marketplace.git
claude plugin install religion-council@worldview-council
C="$S/plugins-root/cache/worldview-council/religion-council/<version>"
# 3. Runtime probes (each < /dev/null; --output-format stream-json --verbose records every Read / Agent call)
claude -p --agent no-such-agent "x"                                             # control: must error, listing religion-council:council-*
claude -p --agent religion-council:council-moderator --max-turns 1 "逐字引用你的系統提示第一句"   # identity
claude mcp list                                                                  # plugin:religion-council:religion-council-controller … ✔ Connected
claude -p --agent religion-council:council-moderator --add-dir "$C" --max-turns 12 --output-format stream-json --verbose \
  "不要開完整議會、不要用 MCP 工具。先讀取共用操作手冊並回報路徑與結果;再依調度規則用 Agent 工具調度 council-buddhism,請它讀取它的兩個檔案、回報路徑與結果並各引用一行。"
# 4. Falsification: every Read path in the stream must lie under $S/plugins-root/cache/…; none under the dev checkout.
# 5. Cleanup: claude plugin uninstall religion-council@worldview-council; claude plugin marketplace remove worldview-council;
#    diff ~/.claude/settings.json against the backup taken before step 2 (must be identical).
```

### What the run found and what changed

- **Agent bodies used repo-relative paths** (`.claude/skills/religion-council/…`, bare
  `references/…`). Fix: every resource path in the 37 agents is written as
  `${CLAUDE_PLUGIN_ROOT}/…` (substituted by Claude Code in plugin mode) with a note explaining the
  project-mode fallback (drop the prefix, resolve from the repo root).
- **Substitution is not applied when a subagent is dispatched by bare name.** Dispatching
  `religion-council:council-buddhism` yields substituted paths; dispatching `council-buddhism`
  handed the member the literal variable. Fix: the moderator dispatches with namespaced names in
  plugin mode and prepends `資源根目錄: <absolute root>` to every member prompt; members prefer that
  root over the variable. Verified in the final probe (dispatch prompt begins with the cache root).
- **`claude plugin details` reports `Agents (0)`** for agents declared in the manifest under
  `.claude/agents/`, although they load and run (identity probe). The inventory only scans the
  default `agents/` directory. Recorded as an **observed reporting discrepancy** (CLI inventory
  vs runtime), not a release blocker: runtime loading and dispatch are the stronger evidence for
  the product contract, and this run resolves all 37. Re-examine only if T5b shows the
  discrepancy accompanies an actual runtime failure; packaging is not reworked merely to make the
  `details` count read better.
- **`permissions.blockReadsOutsideWorkingDirectories: true`** was present in the validating
  user's configuration and required `--add-dir` for access to the plugin cache. Workaround for
  such hardened machines: `claude --add-dir <plugin cache root>` or
  `permissions.additionalDirectories`. Behavior under an unmodified/default profile is deferred to
  the clean-machine smoke (T5b); the acceptance run used `--add-dir`.
